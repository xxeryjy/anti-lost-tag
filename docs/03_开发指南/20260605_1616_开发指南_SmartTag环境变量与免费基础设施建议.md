# SmartTag 环境变量与免费基础设施建议

> 优先级：高
> 创建时间：2026-06-05 16:16
> 修改时间：2026-06-05 16:16
> 创建人：Codex

## 1. 文档目标

本文档用于统一 SmartTag 首版在本地开发、测试环境与免费优先部署方案下的环境变量约定，并给出当前阶段可落地的基础设施推荐。

当前阶段最新约定：

1. 所有环境先统一为本地开发模式
2. 首版不对接邮件厂商
3. 邮箱验证与找回密码采用联调固定验证码 `123456`
4. 首版数据库采用 `MySQL`

## 2. 当前环境策略

### 2.1 统一本地开发模式

当前阶段统一约定：

1. `Nuxt 3` 直接运行在当前仓库根目录
2. 统一使用本地 `MySQL`
3. `Redis`、对象存储、GeoIP、邮件全部先走本地 mock 或关闭
4. 不区分开发环境、测试环境、演示环境的云资源配置
5. 先保证页面、接口、Prisma、认证联调跑通
6. 云上免费基础设施建议保留到后续阶段再接入

### 2.2 当前阶段最小运行依赖

建议：

1. Node.js / Nuxt 运行环境
2. 本地 MySQL
3. Session 密钥
4. 认证 mock 验证码

## 3. 环境变量清单

### 3.1 必需变量

```env
NODE_ENV=development
APP_URL=http://localhost:3000
DATABASE_URL=mysql://root:password@127.0.0.1:3306/smarttag
SESSION_SECRET=replace-with-a-long-random-string
DEFAULT_LOCALE=zh-CN
AUTH_MOCK_CODE=123456
AUTH_ENABLE_EMAIL_VENDOR=false
```

字段说明：

| 变量 | 是否必需 | 说明 |
|------|----------|------|
| `NODE_ENV` | 是 | 运行环境 |
| `APP_URL` | 是 | 站点访问地址 |
| `DATABASE_URL` | 是 | MySQL 连接串 |
| `SESSION_SECRET` | 是 | Session 签名密钥 |
| `DEFAULT_LOCALE` | 是 | 默认语言，建议 `zh-CN` |
| `AUTH_MOCK_CODE` | 是 | 当前联调固定验证码，默认 `123456` |
| `AUTH_ENABLE_EMAIL_VENDOR` | 是 | 是否启用真实邮件厂商，当前固定 `false` |

### 3.2 Redis 相关

```env
REDIS_URL=redis://default:password@host:6379
REDIS_TOKEN=
```

字段说明：

| 变量 | 是否必需 | 说明 |
|------|----------|------|
| `REDIS_URL` | 否 | 扫码去重、限流用 |
| `REDIS_TOKEN` | 否 | 某些托管 Redis 服务需要 |

当前统一本地开发模式下，`Redis` 可以先不启用，相关能力先用内存级 mock 占位。

### 3.3 对象存储相关

```env
STORAGE_PROVIDER=r2
R2_ACCOUNT_ID=
R2_ACCESS_KEY_ID=
R2_SECRET_ACCESS_KEY=
R2_BUCKET=
R2_PUBLIC_URL=
```

字段说明：

| 变量 | 是否必需 | 说明 |
|------|----------|------|
| `STORAGE_PROVIDER` | 否 | 当前建议 `r2` |
| `R2_ACCOUNT_ID` | 否 | Cloudflare 账号 ID |
| `R2_ACCESS_KEY_ID` | 否 | R2 访问密钥 ID |
| `R2_SECRET_ACCESS_KEY` | 否 | R2 访问密钥 |
| `R2_BUCKET` | 否 | 存储桶名称 |
| `R2_PUBLIC_URL` | 否 | 图片公网访问地址 |

### 3.4 GeoIP 相关

```env
GEOIP_PROVIDER=maxmind
MAXMIND_LICENSE_KEY=
GEOIP_DB_PATH=
```

字段说明：

| 变量 | 是否必需 | 说明 |
|------|----------|------|
| `GEOIP_PROVIDER` | 否 | 当前建议 `maxmind` |
| `MAXMIND_LICENSE_KEY` | 否 | 下载 GeoLite2 数据库时使用 |
| `GEOIP_DB_PATH` | 否 | 本地 GeoLite2 数据库文件路径 |

### 3.5 预留变量

以下变量当前阶段可以不启用，但建议预留命名：

```env
MAIL_PROVIDER=none
MAIL_FROM=
MAIL_API_KEY=
SENTRY_DSN=
```

字段说明：

| 变量 | 当前是否启用 | 说明 |
|------|--------------|------|
| `MAIL_PROVIDER` | 否 | 未来若开启真实邮件发送再启用 |
| `MAIL_FROM` | 否 | 发件地址 |
| `MAIL_API_KEY` | 否 | 邮件服务密钥 |
| `SENTRY_DSN` | 否 | 未来错误监控可接入 |

## 5. 后续可选的免费基础设施建议

### 5.1 应用托管

推荐：

1. `Vercel Hobby`

原因：

1. 对 `Nuxt 3` 部署门槛低
2. 前后端一体项目更容易先跑起来
3. 首版联调速度快

### 5.2 MySQL

推荐优先级：

1. 本地开发直接使用本机 MySQL
2. 测试或演示环境优先尝试 `Oracle Cloud Free Tier MySQL`
3. 如果免费 MySQL 托管申请或使用成本偏高，再考虑 `TiDB Cloud Starter`

说明：

1. `Oracle Cloud Free Tier MySQL` 更贴近“真正的 MySQL”
2. `TiDB Cloud Starter` 是 MySQL 兼容方案，不是原生 MySQL
3. 如果你现阶段只是先做页面和接口联调，本地 MySQL 是最省事的

### 5.3 Redis

推荐：

1. `Upstash Redis Free`

适用原因：

1. 足够支撑首版去重与限流
2. 接入简单
3. 免费额度适合演示和早期联调

### 5.4 对象存储

推荐：

1. `Cloudflare R2`

适用原因：

1. 免费额度友好
2. 很适合存储宠物或物品图片
3. 后续接 CDN 也方便

### 5.5 GeoIP

推荐：

1. `MaxMind GeoLite2`

适用原因：

1. 免费
2. 可本地离线使用
3. 不依赖第三方实时 API 计费

### 5.6 邮件

当前建议：

1. 首版认证流程先不接邮件厂商
2. 验证码固定为 `123456`
3. 扫码提醒邮件也先保留接口与服务层，实际发送先做 mock

## 6. 当前最推荐的组合

如果目标是“先统一本地开发并尽快把项目跑起来”，我最推荐这一套：

1. 应用：本地 `Nuxt 3`
2. 数据库：本地 `MySQL`
3. Redis：先不接
4. 存储：先本地占位
5. GeoIP：先关闭
6. 邮件：关闭，统一 mock

## 7. 结论

对 SmartTag 当前阶段来说，最重要的不是一次性把所有云服务接满，而是先保证：

1. Nuxt 工程能跑起来
2. MySQL 数据结构能落地
3. OpenAPI 与 Prisma 一致
4. 认证流程能用 mock 方式先走通
5. 页面和接口可以联调

等这 5 件事稳定后，再决定要不要把 Redis、对象存储、GeoIP、邮件和云部署逐步补齐，会更稳。
