## 2. 页面总结构

首页建议保持 5 个核心区块：

1. Nav + Hero
2. Manifesto
3. Story Video
4. Mission + Values
5. Our Story + Footer

推荐滚动顺序：

`Nav + Hero -> Manifesto -> Story Video -> Mission + Values -> Our Story + Footer`

## 3. 文案占位使用原则

### 3.1 文案原则

1. 文案只做结构占位，不在本阶段冻结最终品牌文案。
2. 每一屏优先保留“情绪”和“立意”，弱化功能解释。
3. 单屏文案总量控制在可快速浏览的范围内。
4. 若后续仍参考 Meouwow 内容，只可用于内部设计验证，不作为上线内容直接使用。

### 3.2 占位格式建议

为方便后续进入视觉稿，建议文案占位采用以下结构：

1. `Eyebrow`
2. `Heading`
3. `Subheading`
4. `Body`
5. `Action`
6. `Meta`

说明：

1. 并不是每一屏都需要全部字段。
2. 能不用的字段尽量不用，保持页面克制。

### 3.3 长度建议

建议以中文文案为基准控制长度：

1. `Eyebrow`：2 到 6 个字
2. `Heading`：10 到 22 个字
3. `Subheading`：14 到 32 个字
4. `Body`：每段 28 到 70 个字
5. `Action`：2 到 8 个字

## 4. 逐屏文案占位与组件清单

### 4.1 第一屏：Nav + Hero

#### 4.1.1 屏幕目标

第一屏承担以下职责：

1. 用 banner 建立品牌情绪
2. 用最少文字完成首页定调
3. 让导航自然融入首屏，不压过主视觉

#### 4.1.2 文案占位结构

推荐占位如下：

- `Eyebrow`
  示例占位：品牌关键词 / 系列识别短语
- `Heading`
  示例占位：一条品牌主张型标题
- `Subheading`
  示例占位：一句简短的情绪补充文案
- `Action`
  示例占位：Discover / Our Story / Explore
- `Meta`
  示例占位：Scroll 提示

#### 4.1.3 推荐文案数量

建议控制为：

1. `Eyebrow`：可选，1 行以内
2. `Heading`：1 到 2 行
3. `Subheading`：1 到 2 行
4. `Action`：最多 1 个
5. `Meta`：1 个极轻提示

#### 4.1.4 组件清单

本屏建议包含以下组件：

1. `Header / Nav`
2. `Brand Logo`
3. `Anchor Nav List`
4. `Language Switcher`
5. `Light CTA Button`
6. `Hero Background Image`
7. `Hero Overlay`
8. `Hero Copy Block`
9. `Scroll Hint`

#### 4.1.5 组件说明

1. `Header / Nav`
   负责承载品牌、锚点导航和语言切换。
2. `Anchor Nav List`
   桌面端建议 3 项：`Story` `Mission` `Values`。
3. `Language Switcher`
   可做轻量 dropdown，是首页唯一建议保留的 dropdown 类型。
4. `Light CTA Button`
   可选，建议只有一个，样式轻。
5. `Hero Copy Block`
   承载 eyebrow、主标题、副标题和按钮。
6. `Scroll Hint`
   只作为轻交互提示，不承担引导功能。

#### 4.1.6 桌面端布局重点

1. Header 叠在 Hero 顶部。
2. Hero 文案区放左下或中左偏下。
3. banner 图像主体尽量完整，不被文案遮挡。
4. 首屏整体高度建议控制在 `72vh - 84vh`。

#### 4.1.7 移动端布局重点

1. 顶部保留品牌名和汉堡菜单。
2. Hero 文案缩短，避免三段式大文案。
3. 按钮可保留，也可直接移除。
4. 首屏总高度应明显短于桌面端。

#### 4.1.8 设计交付备注

本屏视觉稿中需要重点确认：

1. Header 透明态与滚动态的差异
2. Hero 文案块和图片主体的安全区
3. 语言切换的轻量表现方式

### 4.2 第二屏：Manifesto

#### 4.2.1 屏幕目标

这一屏用于快速建立品牌宣言，不承担功能介绍。

#### 4.2.2 文案占位结构

推荐占位如下：

- `Eyebrow`
  示例占位：Manifesto
- `Heading`
  示例占位：一句品牌立意标题
- `Body`
  示例占位：2 段品牌宣言短文

#### 4.2.3 推荐文案数量

建议控制为：

1. `Eyebrow`：1 行
2. `Heading`：1 行
3. `Body`：2 段以内

#### 4.2.4 组件清单

1. `Section Wrapper`
2. `Section Eyebrow`
3. `Manifesto Heading`
4. `Manifesto Body`

#### 4.2.5 组件说明

1. `Manifesto Body`
   由两段正文组成，不建议拆成卡片或多列。
2. `Section Wrapper`
   负责控制这屏的阅读宽度和上下留白。

#### 4.2.6 桌面端布局重点

1. 单栏排版。
2. 文字区域宽度收窄。
3. 不做多列结构，不插图，不插 quote 卡片。

#### 4.2.7 移动端布局重点

1. 标题和正文保持清晰断层。
2. 每段字数控制住，避免一屏出现大段文字墙。

#### 4.2.8 设计交付备注

本屏重点不是装饰，而是版面节奏。视觉稿里要优先确认文字区宽度与留白比例。

### 4.3 第三屏：Story Video

#### 4.3.1 屏幕目标

这一屏作为品牌故事入口，负责制造视觉停顿和情绪延续。

#### 4.3.2 文案占位结构

推荐占位如下：

- `Heading`
  示例占位：品牌故事标题，可选
- `Action`
  示例占位：播放动作提示
- `Meta`
  示例占位：一句极短说明

说明：

1. 这一屏以视觉为主，文字应明显少于其他屏。
2. 如果视觉稿足够强，标题也可以省略。

#### 4.3.3 推荐文案数量

建议控制为：

1. `Heading`：0 到 1 行
2. `Action`：1 个
3. `Meta`：1 行以内

#### 4.3.4 组件清单

1. `Section Wrapper`
2. `Video Cover Card`
3. `Play Button`
4. `Video Meta Copy`

#### 4.3.5 组件说明

1. `Video Cover Card`
   可用图片、静帧或情绪封面作为占位。
2. `Play Button`
   居中或偏左叠加，不建议做重控件感。
3. `Video Meta Copy`
   只放一句说明，不再补充段落。

#### 4.3.6 桌面端布局重点

1. 以单一大图卡为主。
2. 不拆成左右图文结构。
3. 整体宽度略小于 Hero，形成节奏变化。

#### 4.3.7 移动端布局重点

1. 转为纵向图卡。
2. 播放按钮居中。
3. 文案尽量只保留一句。

#### 4.3.8 设计交付备注

本屏需要重点确认封面比例、圆角和 hover 层次是否足够轻。

### 4.4 第四屏：Mission + Values

#### 4.4.1 屏幕目标

这一屏将原本分散的使命、愿景、价值观整合成一个更紧凑的内容区。

#### 4.4.2 文案占位结构

推荐占位如下：

- `Eyebrow`
  示例占位：Mission / Philosophy / Values
- `Heading`
  示例占位：一句使命或愿景主陈述
- `Body`
  示例占位：1 段补充说明
- `Meta`
  示例占位：2 到 3 条 value 标题与简短解释

#### 4.4.3 推荐文案数量

建议控制为：

1. 左栏 `Heading`：1 行
2. 左栏 `Body`：1 段
3. 右栏 `Values`：2 到 3 条
4. 每条 value：标题 + 1 句解释

#### 4.4.4 组件清单

1. `Section Wrapper`
2. `Split Layout`
3. `Mission Copy Block`
4. `Values List`
5. `Value Item`

#### 4.4.5 组件说明

1. `Split Layout`
   桌面端采用左右双栏，移动端转上下结构。
2. `Mission Copy Block`
   集中展示使命或愿景的主陈述。
3. `Values List`
   不建议做大面积卡片墙，可做轻分组列表。
4. `Value Item`
   每项只保留最小必要信息，不扩展成长说明。

#### 4.4.6 桌面端布局重点

1. 左栏宽度可略大于右栏，或保持接近 5:5。
2. 左栏以大段落建立立意，右栏以短信息承接。
3. 用间距和分组建立结构，不依赖重边框。

#### 4.4.7 移动端布局重点

1. 先出现 Mission，再出现 Values。
2. Value 数量控制在 2 到 3 个。
3. 每个 value 不要出现两段以上文字。

#### 4.4.8 设计交付备注

本屏视觉稿需要确认：

1. 左右信息量是否均衡
2. Values 是否足够轻，不会重新变成功能卡片区

### 4.5 第五屏：Our Story + Footer

#### 4.5.1 屏幕目标

这一屏作为页面收束区，负责完成品牌故事的最后落点，并平静进入 footer。

#### 4.5.2 文案占位结构

推荐占位如下：

- `Eyebrow`
  示例占位：Our Story
- `Heading`
  示例占位：结尾段标题
- `Body`
  示例占位：2 段故事性文字
- `Meta`
  示例占位：一句收束句

Footer 占位如下：

- `Brand`
  示例占位：品牌名
- `Links`
  示例占位：邮箱 / 社媒 / 语言 / 版权

#### 4.5.3 推荐文案数量

建议控制为：

1. `Eyebrow`：1 行
2. `Heading`：1 行
3. `Body`：2 段
4. `Meta`：1 句
5. Footer 链接：4 组以内

#### 4.5.4 组件清单

1. `Section Wrapper`
2. `Story Copy Block`
3. `Closing Statement`
4. `Footer`
5. `Footer Brand`
6. `Footer Link Group`
7. `Footer Language`
8. `Footer Copyright`

#### 4.5.5 组件说明

1. `Story Copy Block`
   以文字为主，不建议增加额外图片模块。
2. `Closing Statement`
   作为故事后的情绪收束句，字号可略大。
3. `Footer Link Group`
   保持极简，不做多列网站地图。

#### 4.5.6 桌面端布局重点

1. Story 区建议单栏居中，整体更安静。
2. Footer 可做左右分布，但内容要少。
3. Footer 不宜做成新的重区块。

#### 4.5.7 移动端布局重点

1. Story 保持单栏。
2. Footer 垂直堆叠。
3. 链接数量保持克制，避免底部过重。

#### 4.5.8 设计交付备注

本屏重点是“自然结束”，不是“再开一屏”。视觉稿里要控制好 Story 到 Footer 的衔接距离。

## 5. 页面级组件总清单

为便于后续进入实现或做设计资源拆分，建议首页组件从页面级角度整理如下：

1. `HomeHeader`
2. `BrandLogo`
3. `AnchorNav`
4. `LanguageSwitcher`
5. `HeroSection`
6. `HeroCopyBlock`
7. `ScrollHint`
8. `ManifestoSection`
9. `StoryVideoSection`
10. `MissionValuesSection`
11. `ValuesList`
12. `StoryFooterSection`
13. `Footer`

说明：

1. 当前只是设计阶段组件拆分，不代表最终代码一定按此命名。
2. 这些组件更像“视觉区块单元”，便于后续对齐稿件和实现边界。

## 6. 不建议进入本版首页的内容

以下内容建议继续排除在这版首页之外：

1. Hero 指标数据
2. 产品三步流程
3. Demo 标签预览
4. 找回场景卡片
5. FAQ 区
6. 强营销型 Contact CTA
7. 大量功能说明卡片

原因：

1. 会破坏“简约、紧凑”的页面节奏
2. 会把首页重新拉回产品功能说明页

## 7. 设计交付检查清单

在视觉稿阶段，建议逐项检查：

1. 每一屏是否都能在 3 秒内看懂主旨
2. 是否有任意一屏文案过长，形成文字墙
3. 导航是否足够轻，且没有抢过 Hero
4. Story Video 是否足够简洁，没有变成功能模块
5. Mission + Values 是否仍保持品牌表达，而不是 feature 列表
6. Footer 是否足够薄，收尾是否自然

## 8. 下一步建议

在本文档确认后，建议进入以下任一步骤：

1. 输出首页低保真线框稿说明
2. 输出桌面端 / 移动端的模块尺寸关系说明
3. 进入视觉稿设计
4. 视觉稿确认后再开始 `pages/index.vue` 改版实现
