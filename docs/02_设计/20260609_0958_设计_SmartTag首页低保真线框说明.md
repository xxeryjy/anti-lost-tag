## 2. 页面总结构

首页保持 5 个核心区块：

1. Nav + Hero
2. Manifesto
3. Story Video
4. Mission + Values
5. Our Story + Footer

推荐滚动顺序：

`Nav + Hero -> Manifesto -> Story Video -> Mission + Values -> Our Story + Footer`

## 3. 线框使用原则

### 3.1 目标

低保真线框不处理具体视觉样式，而是先确定：

1. 内容放置关系
2. 信息层级
3. 区块比例
4. 桌面端与移动端的收放方式

### 3.2 页面气质控制

这版首页的线框需要服务于以下目标：

1. 简约
2. 紧凑
3. 品牌感
4. 可阅读

因此在线框层面要避免：

1. 模块过多
2. 卡片过多
3. 一屏内信息关系过碎
4. 不必要的二级结构

### 3.3 页面节奏建议

建议整页节奏控制为：

1. `1 个重点首屏`
2. `2 个短区块`
3. `1 个中等信息区块`
4. `1 个收束区块`

整体滚动长度应明显短于当前首页。

## 4. 桌面端低保真线框

### 4.1 第一屏：Nav + Hero

#### 4.1.1 结构目标

首屏负责品牌定调，必须保证视觉中心明确、导航足够轻、信息足够少。

#### 4.1.2 桌面端结构示意

```text
+--------------------------------------------------------------+
| Logo                  Story  Mission  Values    Lang  Button |
|                                                              |
|   [Eyebrow]                                                  |
|   [Main Heading 1-2 lines]                                   |
|   [Subheading 1-2 lines]                                     |
|   [Light CTA]                                                |
|                                                              |
|                                              Hero Image      |
|                                              Main Subject    |
|                                                              |
|                    [Scroll Hint]                             |
+--------------------------------------------------------------+
```

#### 4.1.3 结构说明

1. Header 覆盖在 Hero 顶部。
2. 左侧为文案区，右侧和中部主要交给 banner 图像。
3. 文案区宽度建议控制在内容区的 `30% - 40%`。
4. Header 与 Hero 共用一个视觉场。

#### 4.1.4 高度建议

1. 整屏总高度：`72vh - 84vh`
2. Header 高度：`56px - 60px`
3. 文案块垂直位置：中下段偏左

#### 4.1.5 对齐建议

1. Header 左右边距与正文内容边距保持一致。
2. Hero 文案左边缘与后续区块正文左边缘尽量对齐。
3. Scroll Hint 可居中，也可跟随文案区左对齐。

### 4.2 第二屏：Manifesto

#### 4.2.1 结构目标

这一屏作为短宣言区，重点是阅读节奏，不做视觉复杂度。

#### 4.2.2 桌面端结构示意

```text
+--------------------------------------------------------------+
|                [Eyebrow]                                     |
|                [Heading 1 line]                              |
|                                                              |
|                [Body paragraph 1]                            |
|                                                              |
|                [Body paragraph 2]                            |
+--------------------------------------------------------------+
```

#### 4.2.3 结构说明

1. 采用单栏排版。
2. 内容整体居中，但文字本身可左对齐。
3. 不增加旁侧装饰列，不增加图文并列。

#### 4.2.4 宽度建议

1. 文字列宽建议控制在内容区的 `48% - 60%`
2. 不宜太宽，否则会削弱阅读感

#### 4.2.5 高度建议

1. 该屏应短于首屏
2. 视觉高度建议为 `中短区块`

### 4.3 第三屏：Story Video

#### 4.3.1 结构目标

这屏的作用是让页面“停一下”，不是承载大量信息。

#### 4.3.2 桌面端结构示意

```text
+--------------------------------------------------------------+
|                                                              |
|            +--------------------------------------+          |
|            |                                      |          |
|            |           Video Cover Card           |          |
|            |             [Play Button]            |          |
|            |                                      |          |
|            +--------------------------------------+          |
|                     [Short Meta Copy]                        |
|                                                              |
+--------------------------------------------------------------+
```

#### 4.3.3 结构说明

1. 这一屏只保留一个主卡片。
2. 卡片宽度不宜满屏，需让左右留白形成节奏。
3. 若保留标题，标题应弱于卡片本身。

#### 4.3.4 宽度建议

1. 图卡宽度建议为内容区的 `70% - 82%`
2. 图卡比例建议偏横向

#### 4.3.5 高度建议

1. 该屏高度应接近 Manifesto 或略高
2. 保持中短，不拉成大段内容区

### 4.4 第四屏：Mission + Values

#### 4.4.1 结构目标

将使命与价值观压缩进同一屏，形成全页唯一一个相对有结构感的信息区。

#### 4.4.2 桌面端结构示意

```text
+--------------------------------------------------------------+
| [Eyebrow]                                                    |
|                                                              |
| +-------------------------+ +------------------------------+ |
| | [Heading]               | | [Value 01 Title]            | |
| |                         | | [Value 01 Copy]             | |
| | [Body paragraph]        | |                              | |
| |                         | | [Value 02 Title]            | |
| |                         | | [Value 02 Copy]             | |
| |                         | |                              | |
| |                         | | [Value 03 Title]            | |
| |                         | | [Value 03 Copy]             | |
| +-------------------------+ +------------------------------+ |
+--------------------------------------------------------------+
```

#### 4.4.3 结构说明

1. 左右双栏，但不是两块独立卡片。
2. 左栏偏“立意”，右栏偏“列举”。
3. 右栏 value 项之间用间距分隔即可。

#### 4.4.4 宽度建议

可采用以下任一比例：

1. `5 : 5`
2. `5.5 : 4.5`
3. `6 : 4`

建议优先使用 `5.5 : 4.5`，更适合强调左侧主陈述。

#### 4.4.5 高度建议

1. 这是全页信息量最高的一屏
2. 但整体仍应控制在 `中等高度`
3. 不应演变成第二个长页面核心区

### 4.5 第五屏：Our Story + Footer

#### 4.5.1 结构目标

以较轻的方式完成页面收束，让故事自然落到 footer，而不是额外开启新章节。

#### 4.5.2 桌面端结构示意

```text
+--------------------------------------------------------------+
|                      [Eyebrow]                               |
|                      [Heading]                               |
|                                                              |
|                      [Body paragraph 1]                      |
|                                                              |
|                      [Body paragraph 2]                      |
|                                                              |
|                      [Closing Statement]                     |
|--------------------------------------------------------------|
| Brand                         Email / Social / Lang / Copy   |
+--------------------------------------------------------------+
```

#### 4.5.3 结构说明

1. Story 部分采用单栏居中，更适合安静收尾。
2. Footer 紧跟在 Story 下方，不再单独形成重模块。
3. Closing Statement 可略大于正文，但不应像新标题。

#### 4.5.4 宽度建议

1. Story 文本宽度建议控制在内容区的 `46% - 58%`
2. Footer 左右信息分布尽量简洁

#### 4.5.5 高度建议

1. Story 区为中短
2. Footer 高度应尽量薄

## 5. 移动端低保真线框

### 5.1 第一屏：Nav + Hero

#### 5.1.1 移动端结构示意

```text
+------------------------------+
| Logo                  Menu   |
|                              |
|         Hero Image           |
|                              |
| [Eyebrow]                    |
| [Heading 1-2 lines]          |
| [Subheading 1-2 lines]       |
| [Light CTA optional]         |
|                              |
|       [Scroll Hint]          |
+------------------------------+
```

#### 5.1.2 结构说明

1. 顶部只保留品牌名和菜单按钮。
2. Hero 图仍然优先，但总高度应压缩。
3. 文案不宜过长，避免手机首屏过重。

### 5.2 第二屏：Manifesto

#### 5.2.1 移动端结构示意

```text
+------------------------------+
| [Eyebrow]                    |
| [Heading]                    |
|                              |
| [Body paragraph 1]           |
|                              |
| [Body paragraph 2]           |
+------------------------------+
```

#### 5.2.2 结构说明

1. 保持单栏。
2. 每段之间留足呼吸感。
3. 字数必须比桌面端更克制。

### 5.3 第三屏：Story Video

#### 5.3.1 移动端结构示意

```text
+------------------------------+
| +--------------------------+ |
| |                          | |
| |      Video Cover         | |
| |      [Play Button]       | |
| |                          | |
| +--------------------------+ |
|      [Short Meta Copy]      |
+------------------------------+
```

#### 5.3.2 结构说明

1. 图卡改为纵向或接近方形比例。
2. 只保留一张卡和一句说明。

### 5.4 第四屏：Mission + Values

#### 5.4.1 移动端结构示意

```text
+------------------------------+
| [Eyebrow]                    |
| [Heading]                    |
| [Body paragraph]             |
|                              |
| [Value 01 Title]             |
| [Value 01 Copy]              |
|                              |
| [Value 02 Title]             |
| [Value 02 Copy]              |
|                              |
| [Value 03 Title]             |
| [Value 03 Copy]              |
+------------------------------+
```

#### 5.4.2 结构说明

1. 左右双栏收为单栏堆叠。
2. Mission 放前，Values 放后。
3. 每个 value 保持轻量，避免视觉堆叠。

### 5.5 第五屏：Our Story + Footer

#### 5.5.1 移动端结构示意

```text
+------------------------------+
| [Eyebrow]                    |
| [Heading]                    |
|                              |
| [Body paragraph 1]           |
|                              |
| [Body paragraph 2]           |
|                              |
| [Closing Statement]          |
|------------------------------|
| Brand                        |
| Email                        |
| Social                       |
| Language                     |
| Copyright                    |
+------------------------------+
```

#### 5.5.2 结构说明

1. Story 和 Footer 仍保持连续。
2. Footer 垂直堆叠，不分栏。
3. 底部链接数量严格控制。

## 6. 区块高度与节奏建议

### 6.1 推荐节奏

整页区块高度建议如下：

1. `Nav + Hero`：最大
2. `Manifesto`：短
3. `Story Video`：中短
4. `Mission + Values`：中
5. `Our Story + Footer`：中短

### 6.2 页面长度判断标准

如果线框输出后出现以下情况，说明页面又变长了：

1. Manifesto 出现第 3 段正文
2. Story Video 出现额外标题组或说明组
3. Mission + Values 出现 4 个以上 values
4. Footer 扩展成多列导航

## 7. 关键对齐规则

为保证整页紧凑且有秩序，建议统一以下对齐策略：

1. Header 左边距、Hero 文案左边距、正文区主要左边距尽量统一
2. 单栏区块使用统一内容宽度逻辑
3. 双栏区块内部使用固定列比，不在每屏重新发明结构
4. Footer 与上方 Story 的外边距保持清晰层次，但不要过大

## 8. 设计稿检查清单

在进入正式视觉稿前，建议先按线框检查以下问题：

1. 首屏是否仍然是唯一最强视觉中心
2. 导航是否足够轻，没有压住 banner
3. 页面是否真的缩短为 5 个核心区块
4. Mission + Values 是否控制住，没有再次变成功能展示墙
5. Footer 是否足够薄，结尾是否自然
