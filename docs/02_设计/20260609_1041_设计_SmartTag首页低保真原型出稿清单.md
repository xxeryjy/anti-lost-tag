# SmartTag 首页低保真原型出稿清单

> 优先级：高
> 创建时间：2026-06-09 10:41
> 修改时间：2026-06-09 10:41
> 创建人：Codex

## 1. 文档目的

本文档用于把现有首页设计结论进一步收口为可执行的低保真原型出稿清单，服务两个直接目标：

1. 设计侧可据此直接绘制桌面端与移动端线框原型
2. 前端可据此开始搭建首页结构与响应式页面骨架

本文档仍处于设计阶段，不输出代码，不冻结最终视觉样式。

## 2. 当前结论

### 2.1 是否需要设计原型

需要，但当前阶段优先需要的是低保真原型，而不是高保真视觉稿。

原因如下：

1. 首页结构、信息层级、导航方式、区块节奏已经基本确定
2. 若没有原型，开发阶段仍会反复讨论区块高度、图文比例、移动端折叠方式
3. 低保真原型足以支持首页骨架开发
4. 高保真视觉可在页面骨架稳定后补充

### 2.2 原型能支持到什么程度

低保真原型可以直接支持以下开发内容：

1. 页面区块顺序与锚点结构
2. 桌面端和移动端布局骨架
3. 组件拆分与容器关系
4. `nav` 的展开方式与滚动状态
5. banner 与正文区块的衔接方式

低保真原型暂时不能单独决定以下内容：

1. 最终字体方案
2. 最终颜色与材质层次
3. 图片裁切风格细节
4. 细节动效与 hover 质感

## 3. 原型范围

### 3.1 页面范围

首页保持 5 个核心区块：

1. `Nav + Hero`
2. `Manifesto`
3. `Story Video`
4. `Mission + Values`
5. `Our Story + Footer`

### 3.2 明确保留项

1. 保留现有 banner 作为首屏核心视觉
2. 保留首页顶部导航
3. 保留桌面端与移动端两套布局说明

### 3.3 明确不进入本轮原型的旧模块

以下旧首页内容不进入这版低保真原型：

1. Hero 指标数据
2. Demo Tag 独立展示模块
3. 产品三步流程
4. 找回场景说明
5. 隐私保护说明大区
6. FAQ 大区
7. 强销售型 CTA 联系区

### 3.4 内容使用边界

当前阶段可用 [Meouwow](https://meouwow.com/) 的内容做内部占位与结构参考，但不代表可直接公开上线。若后续进入正式上线，文案、图片、品牌故事需替换为自有内容。

## 4. 出稿总要求

### 4.1 页面气质

原型阶段即应体现以下方向：

1. 简约
2. 紧凑
3. 有品牌感
4. 可快速浏览

### 4.2 出稿原则

1. 少模块，不把首页重新拉成长信息流
2. 少卡片，只有视频区保留一个明确主卡片
3. 少按钮，全页主按钮控制在 `1 - 2` 个视觉重点内
4. 少并列信息，单屏内只保留一个主阅读重点
5. 优先用留白、对齐、比例建立秩序，不靠装饰元素堆层次

### 4.3 原型交付物

本轮建议至少产出以下 4 张线框稿：

1. 首页桌面端默认态
2. 首页桌面端滚动后导航态
3. 首页移动端默认态
4. 首页移动端菜单展开态

## 5. 导航原型要求

### 5.1 桌面端导航

桌面端 `nav` 采用单层结构，不做主菜单 dropdown。

建议结构：

1. 左侧：`Logo / Brand`
2. 中部：`Story` `Mission` `Values`
3. 右侧：`Language Switcher` + 轻量按钮

出稿时必须体现两个状态：

1. 首屏状态
   `nav` 叠在 Hero 上方，背景透明或近透明
2. 滚动状态
   `nav` 变为浅底 sticky，层级更稳定，内容不跳位

### 5.2 移动端导航

移动端采用单层汉堡菜单，不做多级展开。

建议结构：

1. 左侧：品牌名或 Logo
2. 右侧：菜单按钮
3. 展开后：锚点菜单 + 语言切换 + 轻量按钮

### 5.3 是否需要 dropdown

结论如下：

1. 主导航不需要 dropdown
2. 语言切换可以保留轻量 dropdown
3. 若担心页面过紧，可先在线框阶段同时画出“有右侧按钮”和“无右侧按钮”两个版本，再二选一

## 6. 逐屏原型出稿清单

### 6.1 第一屏：Nav + Hero

#### 6.1.1 目标

首屏负责建立品牌感，保留 banner，并在最少文字下完成首页定调。

#### 6.1.2 桌面端必须画出的元素

1. 顶部导航
2. 左侧文案区
3. 右侧或右中区域的 banner 主视觉
4. 一个轻量按钮
5. 滚动提示

#### 6.1.3 桌面端结构关系

1. Header 覆盖在 Hero 顶部
2. Hero 文案区宽度约占内容区 `30% - 40%`
3. banner 主体优先完整展示，不被文案压住
4. 首屏总高度控制在 `72vh - 84vh`

#### 6.1.4 移动端必须画出的元素

1. 顶部品牌与汉堡菜单
2. 缩短后的 Hero 标题
3. 可选轻按钮
4. 竖向裁切后的 banner 视觉区

#### 6.1.5 文案占位建议

1. `Eyebrow`：可选，1 行
2. `Heading`：1 到 2 行
3. `Subheading`：1 到 2 行
4. `Action`：最多 1 个

#### 6.1.6 出稿检查点

1. `nav` 透明态是否压住 banner
2. 文案块与人物/主体是否冲突
3. 移动端首屏是否仍显得紧凑，而不是堆叠过长

### 6.2 第二屏：Manifesto

#### 6.2.1 目标

用最短内容表达品牌宣言，承担首屏后的第一次阅读停顿。

#### 6.2.2 桌面端必须画出的元素

1. Eyebrow
2. 主标题
3. 两段短正文

#### 6.2.3 桌面端结构关系

1. 单栏居中
2. 文字块整体居中，但正文可左对齐
3. 文本宽度控制在内容区 `48% - 60%`
4. 不插图，不加 quote 卡片，不拆双栏

#### 6.2.4 移动端必须画出的元素

1. 标题区
2. 两段较短正文

#### 6.2.5 文案占位建议

1. `Heading`：1 行
2. `Body`：2 段以内
3. 每段长度控制在短段落级别，避免出现文字墙

#### 6.2.6 出稿检查点

1. 这一屏是否足够短
2. 是否仍然保持阅读节奏，而不是变成说明文段落

### 6.3 第三屏：Story Video

#### 6.3.1 目标

让页面节奏停一下，进入情绪展示，而不是继续讲大量信息。

#### 6.3.2 桌面端必须画出的元素

1. 一个主视频封面卡片
2. 居中的播放按钮
3. 一句极短说明文字

#### 6.3.3 桌面端结构关系

1. 整屏只有一个主卡片
2. 卡片宽度控制在内容区 `70% - 82%`
3. 不做图文分栏
4. 不增加第二按钮

#### 6.3.4 移动端必须画出的元素

1. 纵向或更紧凑比例的视频封面
2. 居中播放按钮
3. 一句极短文案

#### 6.3.5 文案占位建议

1. `Heading`：可省略
2. `Meta`：1 行以内
3. 页面重点是画面，不是文案

#### 6.3.6 出稿检查点

1. 视频卡片是否成为清晰视觉焦点
2. 是否因为附加过多文字而破坏“停顿感”

### 6.4 第四屏：Mission + Values

#### 6.4.1 目标

把使命、愿景、价值观压缩为首页唯一一个相对信息型的区块，但仍需保持紧凑。

#### 6.4.2 桌面端必须画出的元素

1. Section Eyebrow
2. 左栏主标题
3. 左栏一段说明
4. 右栏 `3` 条 value 项

#### 6.4.3 桌面端结构关系

1. 左右双栏
2. 建议比例优先使用 `5.5 : 4.5`
3. 左栏偏品牌陈述
4. 右栏偏列表信息
5. value 项之间只用间距分隔，不需要重卡片

#### 6.4.4 移动端必须画出的元素

1. 标题与正文先纵向排
2. `3` 条 value 项依次堆叠
3. 每条只保留标题和 1 句解释

#### 6.4.5 文案占位建议

1. 左栏 `Heading`：1 到 2 行
2. 左栏 `Body`：1 段
3. 右栏 `Values`：3 条固定
4. 每条 `Value`：标题 + 1 句简短说明

#### 6.4.6 出稿检查点

1. 这一屏是否过重
2. 右栏是否因信息太多而像功能表
3. 移动端堆叠后是否仍然顺畅

### 6.5 第五屏：Our Story + Footer

#### 6.5.1 目标

用轻量方式收尾，让页面自然落到 footer，而不是再开一个强销售模块。

#### 6.5.2 桌面端必须画出的元素

1. Eyebrow
2. 标题
3. 两段短正文
4. 一句收束语
5. Footer 信息列

#### 6.5.3 桌面端结构关系

1. Story 部分使用单栏居中
2. 文字宽度控制在内容区 `46% - 58%`
3. Footer 紧接下方，不单独拉成重区块
4. Footer 内信息保持单行或双列轻量分布

#### 6.5.4 移动端必须画出的元素

1. 标题与正文纵向排布
2. Footer 信息折成上下结构
3. 联系与语言入口保持轻量，不做复杂链接云

#### 6.5.5 文案占位建议

1. `Heading`：1 行
2. `Body`：2 段以内
3. `Closing Statement`：1 行

#### 6.5.6 出稿检查点

1. 是否自然收尾
2. Footer 是否过重
3. 最后一屏是否还保持简约和紧凑

## 7. 开发可用边界

### 7.1 可以直接开始开发的部分

只要低保真原型完成到本文档要求的粒度，前端即可开始：

1. 首页锚点结构搭建
2. `nav` 与 Hero 骨架开发
3. 五个区块的响应式容器开发
4. 文案占位与图片区占位布局
5. 移动端菜单展开结构

### 7.2 建议等待视觉进一步确认的部分

以下内容建议等轻量视觉稿后再收口：

1. 颜色 token
2. 字体与字号最终级差
3. 按钮材质与边框细节
4. hover 与滚动动效细节
5. 视频封面与图片裁切风格

## 8. 建议工作顺序

建议按以下顺序推进：

1. 先画桌面端低保真原型
2. 再画移动端低保真原型
3. 单独补 `nav` 的 4 个状态图
4. 前端按线框搭页面骨架
5. 最后补轻量视觉稿，统一样式细节

## 9. 本轮结论

结论非常明确：

1. 需要设计原型
2. 当前优先做低保真原型
3. 低保真原型完成后即可支持首页界面骨架开发
4. 高保真视觉稿不是当前阻塞项
