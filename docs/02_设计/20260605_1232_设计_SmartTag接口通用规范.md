## 2. 适用范围

本文档适用于首版所有 HTTP API，包括：

1. 主人端认证接口
2. 标签激活与管理接口
3. Finder 公开接口
4. 扫码日志接口
5. 匿名留言接口
6. 图片上传接口

## 3. 基础约定

### 3.1 Base URL

```text
/api
```

### 3.2 传输格式

- 请求体使用 `application/json`
- 文件上传使用 `multipart/form-data`
- 响应体统一使用 `application/json`
- 时间字段统一使用 ISO 8601 UTC 字符串

示例：

```json
{
  "createdAt": "2026-06-05T04:12:30.000Z"
}
```

### 3.3 字段命名风格

统一使用 `camelCase`。

示例：

- `preferredLocale`
- `activationCode`
- `notificationSuppressed`

### 3.4 ID 与路径参数约定

统一遵循以下规则：

1. 对外公开二维码使用 `uid`。
2. 主人端管理接口内部主键仍可使用 `id`。
3. 公开接口路径优先使用 `:uid`。
4. 主人端管理接口路径优先使用 `:id`。

示例：

- `GET /api/tags/public/:uid`
- `PATCH /api/tags/:id/profile`

## 4. 鉴权与会话规范

### 4.1 鉴权方式

首版建议使用 **HttpOnly Cookie Session**。

原因：

1. Nuxt 3 + Nitro 集成成本低。
2. 主人端主要是 Web 场景，不强依赖移动端 App Token。
3. Finder 公开接口天然支持匿名访问，不需要统一到 JWT。

### 4.2 鉴权分类

| 接口类别 | 是否需要登录 |
|------|--------------|
| Finder 公开信息接口 | 否 |
| 扫码日志提交接口 | 否 |
| 匿名留言接口 | 否 |
| 注册、登录、登出接口 | 否 |
| 标签激活接口 | 是 |
| 主人端标签管理接口 | 是 |
| 图片上传接口 | 是 |

### 4.3 Session 行为建议

建议 Session 中至少保存以下信息：

```json
{
  "userId": 1,
  "email": "owner@example.com",
  "preferredLocale": "EN"
}
```

### 4.4 未登录响应

当接口要求登录但当前用户未登录时，统一返回：

- HTTP 状态码：`401`
- 业务错误码：`UNAUTHORIZED`

## 5. 多语言规范

### 5.1 支持语言

首版支持以下语言：

| 文案语言 | 接口枚举值 |
|------|------------|
| 简体中文 | `ZH_CN` |
| 英文 | `EN` |
| 日文 | `JA` |

### 5.2 请求语言来源优先级

建议按以下顺序确定响应语言：

1. 已登录用户的 `preferredLocale`
2. 请求头 `Accept-Language`
3. 系统默认语言 `EN`

### 5.3 接口是否直接返回多语言内容

首版建议分两类：

1. 业务数据字段本身不做多语言化，例如 `displayName`、`medicalNote`，按主人填写原文返回。
2. 系统提示文案、错误消息、邮件模板、默认按钮文案走 i18n。

这意味着：

- OpenAPI 中要描述“错误码稳定、错误消息可多语言变化”
- 页面不要依赖精确匹配 `message` 文案，应该依赖 `error.code`

## 6. 统一响应结构

### 6.1 成功响应

```json
{
  "success": true,
  "data": {},
  "meta": {
    "requestId": "req_01JX1234567890",
    "timestamp": "2026-06-05T04:12:30.000Z"
  }
}
```

### 6.2 失败响应

```json
{
  "success": false,
  "error": {
    "code": "INVALID_PARAMS",
    "message": "参数错误"
  },
  "meta": {
    "requestId": "req_01JX1234567890",
    "timestamp": "2026-06-05T04:12:30.000Z"
  }
}
```

### 6.3 设计原则

1. `success` 是首层快速判断字段。
2. 业务成功时只读 `data`。
3. 业务失败时只读 `error.code` 与 `error.message`。
4. `meta.requestId` 用于日志追踪。
5. `meta.timestamp` 用于排障和客户端调试。

## 7. 分页规范

### 7.1 适用接口

以下接口建议统一走分页结构：

- `GET /api/tags/my`
- `GET /api/tags/:id/scans`
- 后续如增加匿名留言列表，也复用同一结构

### 7.2 分页请求参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `page` | number | `1` | 页码，从 1 开始 |
| `pageSize` | number | `20` | 每页数量 |

### 7.3 分页响应结构

```json
{
  "success": true,
  "data": {
    "list": [],
    "pagination": {
      "page": 1,
      "pageSize": 20,
      "total": 56,
      "totalPages": 3
    }
  },
  "meta": {
    "requestId": "req_01JX1234567890",
    "timestamp": "2026-06-05T04:12:30.000Z"
  }
}
```

### 7.4 分页参数限制

建议：

- `page >= 1`
- `pageSize >= 1`
- `pageSize <= 100`

## 8. 通用错误码规范

### 8.1 首版核心错误码

| 错误码 | HTTP 状态码 | 说明 |
|------|-------------|------|
| `INVALID_PARAMS` | `400` | 参数格式错误或缺失 |
| `UNAUTHORIZED` | `401` | 未登录或登录失效 |
| `FORBIDDEN` | `403` | 无权限访问该资源 |
| `NOT_FOUND` | `404` | 资源不存在 |
| `TAG_NOT_FOUND` | `404` | 标签不存在 |
| `TAG_INACTIVE` | `400` | 标签未激活 |
| `TAG_ALREADY_BOUND` | `409` | 标签已被绑定 |
| `INVALID_ACTIVATION_CODE` | `400` | 激活码错误 |
| `PROFILE_NOT_FOUND` | `404` | 标签资料不存在 |
| `RATE_LIMITED` | `429` | 请求过于频繁 |
| `UPLOAD_NOT_ALLOWED` | `400` | 上传文件不符合要求 |
| `INTERNAL_ERROR` | `500` | 服务器内部错误 |

### 8.2 错误响应设计原则

1. HTTP 状态码表达协议层语义。
2. `error.code` 表达业务层语义。
3. 前端逻辑判断优先依赖 `error.code`。
4. 同一个错误码在不同语言下，`message` 可以不同。

## 9. 核心枚举冻结

### 9.1 与 Prisma 对齐的枚举

| 枚举名 | 可选值 |
|------|--------|
| `PreferredLocale` | `ZH_CN` `EN` `JA` |
| `TagStatus` | `INACTIVE` `ACTIVE` `LOST` |
| `ProfileCategory` | `PET` `ITEM` |
| `PetKind` | `CAT` `DOG` `OTHER` |
| `ProfileSex` | `MALE` `FEMALE` `UNKNOWN` |
| `LocationSource` | `GPS` `IP` |
| `NotificationStatus` | `PENDING` `SENT` `FAILED` `SKIPPED` |
| `DeliveryStatus` | `PENDING` `SENT` `FAILED` |

### 9.2 隐私模式字段约定

当前 Prisma 使用：

```text
privacyMode: boolean
```

首版统一解释为：

- `false`：Direct Contact，允许 Finder 看到公开联系人
- `true`：Privacy Mode，不直接暴露真实电话或邮箱，只允许匿名留言转发

## 10. Finder 公开接口规范

### 10.1 公开接口能力边界

Finder 公开接口只返回“可以给陌生人看的信息”，不返回以下字段：

1. `activationCode`
2. 主人后台内部主键
3. 完整邮箱地址
4. 隐私模式下的真实电话
5. 不允许公开的家庭住址

### 10.2 Finder 页公开返回建议字段

建议至少包含：

- 标签公开状态
- 对象展示名称
- 对象类型
- 图片
- 医疗备注
- 微芯片信息
- 联系方式展示能力
- `showLocation` 按钮所需地图链接或坐标结果
- 是否允许匿名留言

### 10.3 丢失模式展示规则

当 `tag.status = LOST` 时：

1. Finder 页顶部显示巨大红色横幅 `I AM LOST, PLEASE HELP!`
2. 接口返回中应包含 `isLost: true`
3. 前端不应自行从别的字段拼推状态

## 11. 扫码日志规范

### 11.1 扫描日志提交时机

建议流程：

1. 页面先拉取公开资料
2. 再请求浏览器定位
3. 最后提交扫描日志

### 11.2 扫描日志字段约定

与 Prisma 对齐，建议接口层至少支持：

| 字段 | 说明 |
|------|------|
| `locationSource` | `GPS` 或 `IP` |
| `latitude` | GPS 纬度 |
| `longitude` | GPS 经度 |
| `city` | 城市名 |
| `region` | 省州区域 |
| `country` | 国家 |
| `mapUrl` | 当前扫描位置地图链接 |
| `userAgent` | 浏览器标识 |

### 11.3 通知去重规则

首版建议统一为：

- 同一 `tagId + ipAddress` 在 1 分钟内重复扫描，只记录日志，不重复发送提醒

因此接口实现层需要支持：

1. 日志照常入库
2. `notificationSuppressed = true`
3. `notificationStatus = SKIPPED`

## 12. 匿名留言规范

### 12.1 触发条件

仅当：

1. 标签已绑定
2. `privacyMode = true`
3. 主人存在可接收通知的邮箱

时，才允许提交匿名留言。

### 12.2 请求字段建议

| 字段 | 必填 | 说明 |
|------|------|------|
| `finderName` | 否 | 发现者姓名 |
| `finderContact` | 否 | 发现者联系方式 |
| `message` | 是 | 留言正文 |

### 12.3 安全与风控建议

首版建议：

1. 按 `IP + uid` 限频
2. 过滤空消息
3. 设定最大长度，如 `1000` 字符
4. 保留 `scanLogId` 关联，便于审计

## 13. 上传接口规范

### 13.1 首版上传范围

首版只支持标签资料图片上传。

### 13.2 上传限制建议

| 项目 | 建议 |
|------|------|
| 文件类型 | `image/jpeg` `image/png` `image/webp` |
| 单文件大小 | `<= 5MB` |
| 上传角色 | 仅登录主人 |
| 存储位置 | S3 / Cloudflare R2 |

### 13.3 上传响应建议

```json
{
  "success": true,
  "data": {
    "url": "https://cdn.example.com/tags/2026/06/photo.webp"
  },
  "meta": {
    "requestId": "req_01JX1234567890",
    "timestamp": "2026-06-05T04:12:30.000Z"
  }
}
```

1. `servers`
2. `securitySchemes`

4. 通用 `Pagination`
5. 全部核心枚举 `schemas`
6. 认证接口
7. 标签激活与管理接口
8. Finder 公开接口
9. 扫码日志接口
10. 匿名留言接口
11. 上传接口
