# SmartTag 首页视觉设计说明

> 优先级：高
> 创建时间：2026-06-05 18:13
> 修改时间：2026-06-05 18:13
> 创建人：Codex

## 1. 概述

本文档用于冻结 SmartTag 首页 `/` 的视觉设计方向，作为当前设计阶段的统一依据。

本次首页改版基于以下前提：

1. 内容层面在设计阶段完整参考 [Meouwow 官网](https://meouwow.com/) 当前首页叙事内容。
2. 视觉排版不直接复制参考站，而是重新设计为更适合当前项目的简约、紧凑版首页。
3. 当前首页 banner 图保留，继续使用现有主视觉资源。
4. 当前阶段只输出视觉与结构设计说明，不进入代码实现。

## 2. 设计目标

### 2.1 改版目标

本次首页目标不是继续强化“产品功能说明”，而是把首页重心切换到“品牌气质展示”。

首页需要完成的事情：

1. 让用户在首屏快速感知温暖、陪伴、可信的品牌氛围。
2. 用更短、更克制的内容完成品牌叙事。
3. 保留现有 banner 的情绪价值，同时弱化当前功能落地页气质。
4. 建立一套简约、紧凑、可继续扩展的首页视觉框架。

### 2.2 非目标

本次首页不承担以下任务：

1. 不重点解释 SmartTag 具体功能流程。
2. 不通过首页完成强转化或强运营引导。
3. 不在首页展示完整 FAQ、流程说明、场景说明、隐私功能细节。
4. 不在本阶段讨论实现组件、接口和开发排期。

## 3. 设计关键词

本次首页建议统一围绕以下关键词设计：

1. 简约
2. 紧凑
3. 温暖
4. 可信
5. 品牌感
6. 轻编辑感

对应的设计表现建议：

1. 模块数量减少，不做长页面堆叠。
2. 信息密度适中，不空，但也不挤。
3. 文案缩短，优先保留情绪和立意。
4. 少卡片、少边框、少按钮、少图标。
5. 用留白、节奏和图文比例建立层次，而不是用大量装饰。

## 4. 页面定位调整

当前首页更接近“功能说明型长页”，新版首页建议调整为“品牌展示型首页”。

### 4.1 当前页特征

当前首页主要包含：

1. Hero
2. Manifesto
3. Mission / Vision
4. Core Values
5. Flow
6. Scenario
7. Privacy
8. Story
9. FAQ
10. Contact

### 4.2 新版页特征

新版首页建议压缩为 5 个核心区块：

1. Nav + Hero
2. Manifesto
3. Story Video
4. Mission + Values
5. Our Story + Footer

这样的结构更符合“简约、紧凑”的目标，也更适合当前保留 banner、重做视觉的需求。

## 5. 整体信息架构

推荐首页滚动顺序如下：

`Nav + Hero -> Manifesto -> Story Video -> Mission + Values -> Our Story + Footer`

### 5.1 节奏说明

整页节奏建议采用“1 个重点首屏 + 4 个压缩区块”的结构：

1. 首屏负责抓住情绪。
2. 第二屏快速建立品牌宣言。
3. 第三屏用视频入口制造视觉停顿。
4. 第四屏集中承接使命与价值观。
5. 最后一屏用短故事与极简 footer 收束。

### 5.2 建议删除或降级的旧模块

以下内容不建议继续出现在首页主结构中：

1. Hero 数据指标
2. Demo Tag 预览
3. 产品三步流程
4. 找回场景说明
5. 隐私保护功能说明
6. FAQ 大区
7. 强 CTA 联系区

如果后续业务必须保留相关内容，建议迁移到二级页面，而不是继续占用首页主叙事。

## 6. 导航设计

导航是本次首页气质的关键部分，必须与“简约、紧凑、品牌感”保持一致。

### 6.1 总体原则

1. 主导航不做 dropdown。
2. 导航高度收窄，整体更轻。
3. 导航作为首屏的一部分出现，而不是独立压住内容。
4. 桌面端以锚点导航为主，移动端以单层抽屉菜单为主。

### 6.2 桌面端导航结构

推荐结构：

1. 左侧：品牌名 / Logo
2. 中间：`Story` `Mission` `Values`
3. 右侧：语言切换 + 轻按钮

说明：

1. 主导航项控制在 3 个，最多不超过 4 个。
2. 这 3 个一级项足够覆盖当前压缩后的首页结构。
3. 语言切换可以做小型 dropdown，但不参与主视觉竞争。

### 6.3 桌面端导航样式

建议：

1. 导航视觉高度控制在 `56px - 60px`。
2. 初始状态透明，悬浮在 Hero 之上。
3. 向下滚动后转为浅色半透明 sticky header。
4. 字号偏小，字距略放大，体现克制感。
5. 右侧按钮使用轻描边或纯文字样式。

不建议：

1. 不建议主导航做多级 dropdown。
2. 不建议导航里出现 5 个以上菜单项。
3. 不建议在首页头部放两个以上 CTA。
4. 不建议使用厚重投影、明显底色和粗线边框。

### 6.4 移动端导航结构

推荐结构：

1. 左：品牌名 / Logo
2. 右：汉堡菜单按钮

菜单展开后只保留单层结构：

1. Story
2. Mission
3. Values
4. Language

说明：

1. 移动端不建议多级展开。
2. 导航的重点是清晰和轻量，不是站点树展示。
3. 如果后续恢复更多站点页面，再单独讨论移动端信息架构扩展。

## 7. 首屏设计

首屏由 `Nav + Hero` 共同组成，既要保留 banner 的情绪，也要体现页面整体的“紧凑感”。

### 7.1 首屏目标

1. 第一时间建立品牌气氛。
2. 让用户感知温暖、陪伴、生活方式感。
3. 控制信息量，避免首屏变成功能说明区。

### 7.2 Hero 内容组成

建议首屏只保留以下内容：

1. 小眉标题，可选
2. 主标题
3. 一句副标题
4. 一个轻按钮，可选
5. 一个很轻的向下提示

不建议保留：

1. 双按钮
2. 指标数据
3. 功能清单
4. 长描述
5. 产品演示入口

### 7.3 桌面端 Hero 布局

建议：

1. banner 作为主视觉背景，占据页面主要视觉面积。
2. 文案放在左下或中左偏下区域。
3. 文案宽度适中，不要过宽。
4. 图片主体区域保持通透，不叠加过多元素。

首屏高度建议：

1. 不建议做过空的全屏剧场式首屏。
2. 桌面端整体高度控制在 `72vh - 84vh` 更合适。
3. 在保证气氛的同时，减少“空屏感”。

### 7.4 移动端 Hero 布局

建议：

1. 主视觉图优先完整保留。
2. 文案放在图片安全区域内，或落到图片下方。
3. 缩短首屏总高度，避免手机端只看到一整屏大图。
4. 主标题长度比桌面端更短，副标题只保留一句。

### 7.5 Banner 处理建议

1. 在现有 banner 上增加暖色渐层蒙版。
2. 适度压暗局部背景，提高文案可读性。
3. 整体氛围偏柔和，不要做强对比处理。

## 8. 区块设计

### 8.1 Manifesto

#### 目标

快速建立品牌宣言，不拉成长文说明。

#### 内容结构

1. 小标题：Manifesto
2. 主标题：1 行
3. 正文：2 段以内

#### 布局建议

1. 使用单栏布局。
2. 内容宽度收窄，控制阅读节奏。
3. 上下留白要有，但不做奢侈型大留白。

#### 不建议

1. 不做 quote 卡片。
2. 不做多列文案。
3. 不插入额外功能说明。

### 8.2 Story Video

#### 目标

作为视觉停顿区，承接品牌叙事。

#### 内容结构

1. 一张主视觉封面
2. 一个播放按钮
3. 一句极短说明

#### 布局建议

1. 保持为单一完整图卡。
2. 桌面端不拆成复杂左右结构。
3. 移动端直接转为纵向单卡。

#### 不建议

1. 不增加视频介绍段落。
2. 不增加辅助说明列表。
3. 不增加次级按钮。

### 8.3 Mission + Values

#### 目标

把原本分散的使命、愿景、价值观压缩成一个复合区块。

#### 桌面端布局

左右双栏：

1. 左栏：Mission / Vision
2. 右栏：Values

#### 内容建议

左栏保留：

1. 一个小标题
2. 一句主陈述
3. 一段补充说明

右栏保留：

1. 2 到 3 个核心 values
2. 每个 value 只保留标题和一句解释

#### 设计建议

1. 不做大面积卡片墙。
2. 可使用轻分组和间距代替重边框。
3. 这一屏要有结构感，但不能像后台信息块。

### 8.4 Our Story + Footer

#### 目标

用较短的品牌故事和极简 footer 完成页面收束。

#### Our Story 内容结构

1. 标题
2. 2 段正文
3. 1 句收束句

#### 布局建议

1. 桌面端推荐单栏居中，整体更平静。
2. 移动端保持单栏，不做复杂图文穿插。
3. 这部分以文字为主，不建议再加大量图片。

#### Footer 内容建议

保留：

1. 品牌名
2. 邮箱 / 社媒
3. 语言
4. 版权

不保留：

1. FAQ
2. 多列站点地图
3. 强 CTA 联系区
4. 产品矩阵式入口

## 9. 视觉系统建议

### 9.1 配色方向

建议采用低饱和、偏温暖的品牌配色：

1. 奶油白
2. 暖灰
3. 浅橄榄绿
4. 低饱和棕金
5. 深灰文字色

说明：

1. 整体不走高对比科技蓝路线。
2. 不走强紫色、强荧光色路线。
3. 颜色主要承担氛围，不承担功能区分。

### 9.2 排版方向

建议：

1. 标题数量减少，避免每屏都是大标题。
2. 正文控制在较短段落，增强阅读效率。
3. 英文字可略拉字距，强化品牌感。
4. 中英文混排时保持节奏统一，不要出现过重 UI 文案感。

### 9.3 间距与密度

建议：

1. 区块间距统一收敛。
2. 组件内部间距要克制，避免松散。
3. 页面视觉密度以“紧凑但可呼吸”为准。

判断标准：

1. 不应像后台卡片列表那样密。
2. 也不应像奢侈品牌官网那样空。

### 9.4 卡片与边框

建议：

1. 少用重边框。
2. 少用投影。
3. 少用大量同构卡片。
4. 优先用留白、浅底和内容分组控制层次。

## 10. 动效与交互建议

### 10.1 动效原则

1. 动效轻，不喧宾夺主。
2. 页面以慢速淡入和轻位移为主。
3. 不使用明显弹跳、缩放和夸张 hover。

### 10.2 推荐动效

1. 首屏文案轻微淡入上移。
2. 导航滚动后平滑切换为 sticky 状态。
3. 区块进入视口时轻微渐显。
4. 视频入口卡片 hover 时做非常轻的层次变化。

### 10.3 不建议

1. 不建议每一块都做明显动画。
2. 不建议按钮使用强烈交互动效。
3. 不建议使用重视差滚动。

## 11. 响应式策略

### 11.1 桌面端

重点保留：

1. Banner 情绪展示
2. 轻量导航
3. 宽窄切换的节奏感

### 11.2 移动端

重点控制：

1. 首屏不要过高
2. 文案进一步缩短
3. 区块数量不变，但视觉表达更直接
4. 所有结构保持单层，不做复杂二级交互

### 11.3 移动端容易出问题的点

1. 文案过长，导致页面像文章页
2. 图片裁切过碎，失去情绪
3. 各区块处理过于统一，导致节奏变平

## 12. 风险与边界

### 12.1 内容风险

如果后续公开上线，直接使用 [Meouwow 官网](https://meouwow.com/) 的完整文案、品牌故事或图片素材，存在明显版权和品牌风险。

因此建议：

1. 设计阶段可先用其内容进行版式与气质验证。
2. 实际开发前需要替换为 SmartTag 自有品牌文案与素材。

### 12.2 业务风险

当前项目仍有 SmartTag 的功能流程、Finder 路由和注册路径。如果首页完全转为品牌页，需要注意首页与后续业务流程之间的认知衔接。

建议：

1. 首页保持品牌叙事。
2. 具体功能和流程说明迁移到二级页。
3. 导航与 footer 保留最少量业务入口。

### 12.3 多语言风险

当前项目存在多语言需求，后续若延续参考站内容，需要同步考虑 `zh-CN / en / ja` 的一致性，不建议只完成单语品牌页后再补翻译。

## 13. 设计结论

本次首页视觉方向建议最终落为：

1. 保留现有 banner 图，作为首页情绪入口。
2. 首页整体收敛为 5 个核心区块。
3. 导航采用简约、紧凑、无主 dropdown 的锚点结构。
4. 视觉上强调温暖、可信、低饱和、少装饰。
5. 页面从功能说明页转为品牌展示页。

## 14. 下一步建议

在本说明文档确认后，建议按以下顺序推进：

1. 输出首页低保真线框稿
2. 确认每一屏的文案占位与图片占位
3. 再进入视觉稿阶段
4. 视觉稿冻结后再进入 `pages/index.vue` 实现
