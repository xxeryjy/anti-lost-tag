## 1. 文档目的

本文档用于把当前首页设计阶段的结论，进一步转换为前端可执行的页面骨架说明，作为后续改造 [pages/index.vue](D:/Demo/anti-lost-tag/pages/index.vue) 的结构依据。

本文档聚焦以下内容：

1. 首页最终建议保留的区块顺序
2. 每一屏推荐的容器结构
3. 每一屏的组件边界
4. `nav` 的状态与交互范围
5. 桌面端与移动端的结构差异
6. 现有首页旧模块的去留建议

当前阶段仍然不输出代码。

## 2. 开发目标

### 2.1 改版目标

首页从当前的“功能介绍型长页”调整为“品牌展示型首页”，保留现有 banner 视觉，但压缩信息密度，突出品牌气质与内容节奏。

### 2.2 页面关键词

前端在理解结构时应始终围绕以下关键词：

1. 简约
2. 紧凑
3. 品牌优先
4. 少模块
5. 少按钮
6. 少卡片

## 3. 首页目标结构

### 3.1 最终保留的 5 个核心区块

首页改版后建议保留以下结构：

1. `Nav + Hero`
2. `Manifesto`
3. `Story Video`
4. `Mission + Values`
5. `Our Story + Footer`

推荐锚点顺序：

1. `#story`
2. `#mission`
3. `#values`

说明：

1. `Manifesto` 可作为自然滚动区块，不一定强制进入顶部导航
2. `Story Video` 与 `Our Story` 在文案上都可归入 `Story` 语义范围

### 3.2 明确删除或降级的现有模块

当前 [pages/index.vue](D:/Demo/anti-lost-tag/pages/index.vue) 中以下内容不建议保留为独立首页模块：

1. Hero 指标区 `heroMetrics`
2. Hero 功能标签 `hero-proof-row`
3. Mission 双卡 + 列表的旧结构
4. Values 五卡片大网格
5. Flow 三步流程区
6. Demo Tag Preview 侧栏
7. Scenario 双场景说明
8. Privacy 区块
9. FAQ 区块
10. Contact 强 CTA 区块

### 3.3 可复用的现有资源

以下内容可优先复用，而不是全部推翻：

1. Hero banner 图片资源 `assets/images/Dog_running@2x.png`
2. 首页基础 SEO 结构
3. 现有 `home.*` i18n 命名方式
4. 基础按钮、容器、排版类名中的可复用样式思路

## 4. 顶层页面骨架建议

### 4.1 页面层级

建议首页骨架按以下顺序组织：

```text
home-page
  home-nav
  home-hero
  home-main
    section-manifesto
    section-story-video
    section-mission-values
    section-our-story
  home-footer
```

### 4.2 结构原则

1. Hero 独立成首屏大区
2. 其余区块放入统一主内容流
3. Footer 不再作为单独强区块，而是归到收尾部分
4. 每一屏尽量只有一个清晰阅读重点

## 5. 导航开发说明

### 5.1 导航结构

桌面端建议结构如下：

```text
home-nav
  nav-brand
  nav-links
    link-story
    link-mission
    link-values
  nav-tools
    language-switcher
    light-cta
```

移动端建议结构如下：

```text
home-nav
  nav-brand
  nav-toggle

mobile-nav-panel
  link-story
  link-mission
  link-values
  language-switcher
  light-cta
```

### 5.2 导航状态

导航至少需要支持 4 种结构状态：

1. 桌面端首屏透明态
2. 桌面端滚动后 sticky 态
3. 移动端默认收起态
4. 移动端菜单展开态

### 5.3 导航交互边界

1. 主导航不做 dropdown
2. 主导航只做单层锚点跳转
3. 语言切换可保留轻量 dropdown
4. 移动端不做多级展开
5. 滚动态只改变背景、阴影、文字对比，不改变布局关系

## 6. 逐屏开发说明

### 6.1 第一屏：Nav + Hero

#### 6.1.1 区块目标

保留 banner，建立品牌定调，并把首页信息压缩到最少。

#### 6.1.2 建议容器结构

```text
section-hero
  hero-media
    hero-image
    hero-overlay
  hero-content
    hero-eyebrow
    hero-heading
    hero-subheading
    hero-action
  hero-scroll-hint
```

#### 6.1.3 必须保留的内容

1. Banner 主视觉
2. Hero 标题
3. Hero 简短说明
4. 1 个轻按钮
5. 滚动提示

#### 6.1.4 必须移除的旧内容

1. Hero 三枚 feature pill
2. Hero 指标卡片
3. 首屏双按钮结构中的强动作堆叠

#### 6.1.5 桌面端布局要求

1. 文案区域在左
2. Banner 主体在右或右中
3. 首屏高度控制在 `72vh - 84vh`
4. 文案宽度控制在内容区 `30% - 40%`

#### 6.1.6 移动端布局要求

1. 标题和说明纵向排布
2. 文案明显缩短
3. Banner 改为更聚焦主体的竖向裁切
4. 按钮可保留 1 个，也可在视觉阶段比较是否移除

### 6.2 第二屏：Manifesto

#### 6.2.1 区块目标

提供一段简短品牌宣言，承担首屏后的阅读缓冲。

#### 6.2.2 建议容器结构

```text
section-manifesto
  manifesto-inner
    manifesto-eyebrow
    manifesto-heading
    manifesto-body
```

#### 6.2.3 必须保留的内容

1. 1 个简短标题
2. 1 到 2 段正文

#### 6.2.4 必须移除的旧内容

1. `quote-card`
2. Manifesto 双栏结构
3. 三段以上正文堆叠

#### 6.2.5 桌面端布局要求

1. 单栏居中
2. 文本宽度控制在内容区 `48% - 60%`
3. 不插图，不放装饰型并列模块

#### 6.2.6 移动端布局要求

1. 仍保持单栏
2. 每段更短
3. 该屏总体高度短于首屏

### 6.3 第三屏：Story Video

#### 6.3.1 区块目标

建立品牌情绪停顿点，让页面从说明进入感受。

#### 6.3.2 建议容器结构

```text
section-story-video
  story-video-inner
    video-cover-card
      video-cover-image
      play-button
    video-meta
```

#### 6.3.3 必须保留的内容

1. 一个视频封面卡片
2. 一个播放按钮
3. 一句极短说明

#### 6.3.4 必须移除的旧内容

1. 不新增并列图文说明
2. 不新增第二操作按钮
3. 不把视频区变成功能介绍模块

#### 6.3.5 桌面端布局要求

1. 居中放置单个主卡片
2. 卡片宽度控制在内容区 `70% - 82%`
3. 文案弱于画面

#### 6.3.6 移动端布局要求

1. 维持单卡片结构
2. 比例更紧凑
3. 只保留一句文案

### 6.4 第四屏：Mission + Values

#### 6.4.1 区块目标

把当前分散的使命、愿景、价值观内容压缩为唯一一个相对信息型区块。

#### 6.4.2 建议容器结构

```text
section-mission-values
  mission-values-inner
    mission-copy-column
      section-eyebrow
      mission-heading
      mission-body
    values-list-column
      value-item-01
      value-item-02
      value-item-03
```

#### 6.4.3 必须保留的内容

1. 左侧使命主陈述
2. 左侧 1 段说明
3. 右侧 3 条 value

#### 6.4.4 必须移除的旧内容

1. `missionCards` 双卡结构
2. `missionBullets` 独立列表卡
3. `valueCards` 五卡网格

#### 6.4.5 桌面端布局要求

1. 左右双栏
2. 推荐比例 `5.5 : 4.5`
3. 右栏只做 3 条 value 列表
4. value 之间只用间距区分，不做重卡片

#### 6.4.6 移动端布局要求

1. 改为纵向堆叠
2. 先标题正文，再 value 列表
3. 每条 value 只保留标题和 1 句解释

### 6.5 第五屏：Our Story + Footer

#### 6.5.1 区块目标

用轻量故事收尾，并自然过渡到 footer。

#### 6.5.2 建议容器结构

```text
section-our-story
  our-story-inner
    story-eyebrow
    story-heading
    story-body
    story-closing

home-footer
  footer-brand
  footer-meta-links
```

#### 6.5.3 必须保留的内容

1. 标题
2. 1 到 2 段故事正文
3. 1 句收束语
4. Footer 品牌信息
5. Footer 轻量联系 / 社媒 / 语言入口

#### 6.5.4 必须移除的旧内容

1. FAQ 区块
2. Contact 强 CTA 区块
3. 再次开启新章节的重标题结构

#### 6.5.5 桌面端布局要求

1. Story 单栏居中
2. 文本宽度控制在内容区 `46% - 58%`
3. Footer 紧贴下方
4. Footer 信息轻量横向分布

#### 6.5.6 移动端布局要求

1. Story 保持单栏
2. Footer 折成上下结构
3. 链接数量保持克制

## 7. 现有首页到新结构的映射建议

### 7.1 可保留并重组的内容

1. 现有 Hero 图片资源保留
2. 现有 `home.story*`、`home.mission*`、`home.values*` 文案语义可择优复用
3. 现有基础 section 排版思路可重组使用

### 7.2 应直接下线的现有结构

1. Flow 展示区
2. Preview 区
3. Scenario 区
4. Privacy 区
5. FAQ 区
6. Contact 区

### 7.3 文案与 i18n 注意事项

若后续进入实现阶段，建议：

1. 不立刻大规模复用旧 i18n key 拼凑新页面
2. 优先按新结构整理一版首页专用 key
3. 参考 Meouwow 的内容仅用于内部设计占位，不直接视为最终上线文案

## 8. 开发顺序建议

如果后续进入实现阶段，建议按以下顺序进行：

1. 先重构首页 section 结构
2. 再接入新的 `nav` 骨架
3. 再处理 Hero 与 banner 的布局
4. 再补 Manifesto、Video、Mission、Story 四个内容区
5. 最后补 footer、滚动态、移动端菜单态

## 9. 本轮结论

到当前为止，首页已经具备以下开发前置条件：

1. 有视觉方向说明
2. 有逐屏文案占位与组件清单
3. 有低保真原型出稿清单
4. 有文字版低保真线框草稿
5. 有面向前端的逐屏线框开发说明

因此下一步如需继续推进，已经可以进入首页实现准备阶段。
